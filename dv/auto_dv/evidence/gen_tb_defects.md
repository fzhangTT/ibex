# TB defect register - the team's own testbench, tests and harness

Defects in the verification environment, not in the DUT. Owner: dv-lead; rows are opened from a measured
failure and land with the fix that closes them. A defect here is a property of `dv/auto_dv/**`, never of the
Ibex core: DUT findings live in `dv/auto_dv/docs/gen_bug_log.md`, whose scope note points here.

Every row states what failed, the mechanism with a file:line citation, and the evidence that survives the fix.
That last part is a rule rather than a habit: a divergence usually stops reproducing once its defect is fixed,
so a row resting on the observed symptom goes stale and a reader a month later cannot tell what was wrong. The
mechanism is what a row is for.

| Ref | Defect | Mechanism | Evidence that survives the fix | Fixed |
|---|---|---|---|---|
| T1 | One bridge cycle-threshold slot is shared by every `wait_cycles` waiter, so a stimulus polling a near target destroys a pending far one and the schedule fires early | `dv/auto_dv/tests/gen_test_template.py` wrote the single slot from each waiter, against the one register at `dv/auto_dv/tb/gen_bridge_if.sv:24-25` and `:77-80` | The fix's own account, in the docstring of `_cycle_slot_service`: "a stimulus polling a near target once stole the runner's far boundary and applied a whole phase group thousands of cycles early". Measured instance: the c11664 phase group applied at cycles 77-82 with `fire_schedule_applied` reporting `ok=False`, "reached 8 of 14 ... applied 14, early" | 2d87642: one service owns the slot, arms the earliest target and wakes only what a hit reaches; waiters register instead of writing. The bridge is unchanged |
| T2 | An interrupt acknowledgement clears every line held until acknowledgement, not the acknowledged one, so a second raised line is cleared and never taken | `dv/auto_dv/env/gen_agents_pkg.sv:607-611`: `ack_seen()` masks every line at level whose hold is `GEN_IRQ_HOLD_UNTIL_ACK` and clears them in one `cmd_clr`. The defect is in the INTERFACE, not the predicate: `ack_seen()` takes no line argument, so it cannot clear only the acknowledged line however the loop is written | Designed as such and outgrown, not an oversight: the handler comment at `:814` reads "set on the irq-ack window: a store releases the UNTIL_ACK lines", plural and present tense. The first test to raise two such lines at once needed per-line acknowledgement. The caller already holds the identifying value, receiving `data` at `:816-820` and storing it as `last_data` before discarding it | e6eb3a2 (landing 41): the store's word is read as the vector cause, mapped to one driver line, and only that line is released. Red gen_ut_irq_ack with gen_irq_ack_directed.S; mutant MUT-ACKALL1; retained log gen_fu_l41_irq_ack_target.log; the failing behaviour is evidenced by dv/auto_dv/evidence/gen_irq_triage/gen_irq_quiet_probes.yaml |
| T3 | The memory agent latches the DUT's fetch address at the falling edge, so it can sample a mid-cycle settling value the DUT never presented at any clock edge | `dv/auto_dv/env/gen_agents_pkg.sv:264`, with the design note at `:194` giving the reason as "the core's posedge outputs are stable" - true of a registered output, false of a combinational one | The delta-ordering argument, which survives because it does not depend on the symptom: the interrupt agent drives the input at the same falling edge, so which value the memory agent reads is decided by delta ordering between two drivers acting at one instant. A slave sampling at the accepting rising edge reads the address the DUT booked and no divergence exists. Observed once at retirement order 548 of the rtl-arch-010 block (dv/auto_dv/evidence/gen_irq_triage/gen_rtl_arch_010_served.yaml for the wave that placed it; dv/auto_dv/evidence/gen_irq_triage/gen_irq_quiet_probes.yaml for the control and the single-variable quiet probe that isolates the interrupt regime, every figure re-measured from the run directories), a divergence that stops reproducing once the sampling is fixed | e6eb3a2 (landing 41). The fix moves addr, we, be, wdata and the memory operation to the accepting rising edge where req and gnt are both sampled high, while every timing figure and the export cycle base stay at the granting falling edge: the VALUE moves and the TIME does not. AUDIT, stated here because the ruling asked for it: gen_bus_driver serves both buses through cfg.is_data, so one change covers instruction and data; every other reader of a DUT output already samples at the posedge (gen_rvfi_pkg.sv:136, gen_checkers_pkg.sv:241 and :476, gen_fcov_pkg.sv:1594), and the remaining four negedge processes drive inputs and read no combinational DUT output for a value. The red is a directed driver unit test with no RTL and no core, in the wave's shape; MUT-LATCHNEG1 is caught by its two moved-address checks and survives a copy with those two checks removed. Red gen_ut_bus_latch_top.sv; retained log gen_fu_l41_bus_latch_instant.log |

Related: the design property behind T3 is recorded as S6 (B21) in `dv/auto_dv/docs/gen_bug_log.md` Section 2.
It is a property and not a defect: the core is self-consistent at every rising edge, nothing documented is
violated, and it is not what made that run fail.
