[minor][dv/auto_dv/flow/gen_run.py:184] A non-zero simv exit code with a clean log and the end marker present yields PASS (`decide()` stores `rc` but never consults it). A crash during coverage-DB write after `$finish` would report PASS on a corrupt vdb. - Treat rc not in {0, 124} on a would-be PASS as a FAIL with reason "nonzero exit with clean log"; that keeps the log-first contract of SIM_RECIPE §5 while adding the exit code as one more collected mechanism.

[minor][dv/auto_dv/flow/gen_testlist.yaml:47] `uvm_test: none` is a string where the schema (line 17) says null means "no UVM test class"; `gen_run.py:44` treats it as truthy and emits `+UVM_TESTNAME=none` (visible in the recorded command). Harmless on the pure-SV top today, misleading once a UVM top exists. - Use `null` and have `load_testlist` reject non-null, non-identifier strings.

[minor][dv/auto_dv/flow/gen_build.py:101] `^Error-\[(\w+)\]` (and the warning regex) misses hyphenated VCS codes such as `Error-[SV-LCM-PND]`; `status` still falls to `failed` through `vcs_rc`, but `error_count`/`error_classes` under-report. - Use `[\w-]+`.

[minor][dv/auto_dv/flow/gen_dashboard.py:67] `dut_scope_row` prefers the `hierarchy.txt` row, which has no GROUP column, so once covergroups exist the dashboard prints functional coverage as n/a while `totals` reports it. - Decide the DUT-scope functional source (`groups.txt` / `-cm_hier`-scoped group totals) before the first covergroup lands; also `load_manifests` (line 26) is annotated `list[...]` but returns a tuple.

[minor][dv/auto_dv/flow/gen_build.py:93] `sweep_side_files` moves any `vcs.key`/`ucli.key`/`constfile.txt` in the clone root newer than the compile start; two compiles from the same clone at once would take each other's side files. - Compile in a per-build cwd, or record and compare inode/mtime per compile.
