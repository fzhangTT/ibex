This branch takes ~7 commits an hour (168 in the last 24 h), each lone head regression and each server batch syncs HEAD-now into a new tree, and a purpose-4 regression runs 45-60 min; six newer trees inside that window deletes the tree a running batch is bound to. Record the count of live leases in the sync log.

[Major][dv/auto_dv/flow/gen_cov_report.py:210] `parse_groups` sets `cols` at the first `SCORE WEIGHT NAME` header and then ingests every later line with three or more tokens whose first two parse as float and int. URG's groups.txt follows the summary table with one "Summary for Group" block per covergroup whose header is `SCORE WEIGHT GOAL AT LEAST PER INSTANCE AUTO BIN MAX PRINT MISSING COMMENT` (no `NAME` token, so `cols` is not reset) and a numeric row such as `5.00 1 100 1 0 64 64`; that row becomes a covergroup named `64` with the group's score and weight. Every group is then counted twice, and the ledger group re-enters the recomputed average under a numeric name, which is exactly what the exclusion is meant to prevent. The fabricated self-test (gen_cov_report.py:351-355) contains only the summary table and cannot see this. I could not verify on site because no groups.txt exists under the out root. - Recommendation: end the table at the first blank or `----` line after the header, reset `cols` on any header line that lacks `NAME`, and require the name token to start with a letter; add a self-test case containing a per-group summary block; replace the fabricated fixture with a real groups.txt excerpt on the first run that carries a covergroup, as the label promises.
