**Findings**

[Major][dv/auto_dv/env/gen_fcov_pkg.sv:1866-1871] CG-PMP-001 cp_outcome is classified by comparing the RAW attempted byte with the pre byte. The DUT never stores bits 6:5 and drops W when R=0 under MML=0, so an attempted byte that differs from the stored byte only in reserved bits (or that equals it after the W drop) leaves post == pre and is booked `ignored_lock` on an unlocked entry or under RLB=1; conversely a W-without-R write that also carries reserved bits fails the `post_b == (a_b & 8'hfd)` test and is booked `written` instead of `w_dropped`. The retained measurement shows exactly this: WARL hits cp_outcome.ignored_lock at 39/39 seeds while cr_lock_outcome.locked_rlb0_ignored hits at 23/39, and mseccfg hits ignored_lock at 7/40 with locked_rlb0_ignored at 0/40. Those are ignored_lock samples with no locked-RLB=0 write behind them. No declared manifest bin rests on a false hit (the lock entry's ignored_lock is backed by locked_rlb0_ignored at 40/40), but the merged-report credit for this coverpoint is inflated, which is the honesty-over-green rule. - Compute the legalised expected byte (mask 0x9f, then W &= R when MML=0); book `written`/`w_dropped` when post == expected; book an `ignored_*` outcome only when post == pre and expected != pre, and gate `ignored_lock` on pre_b[7] && !rlb. Re-run the 40-seed block for CG-PMP-001 after the fix.

[Major][dv/auto_dv/env/gen_fcov_pkg.sv:1687-1689] cp_first_after_reset is one run-wide flag cleared by ANY PMP CSR access. The plan defines it per CSR ("no prior write to this CSR since reset") and cr_reset_read expects rst_pmpcfg, rst_pmpaddr, rst_mseccfg and rst_mseccfgh, i.e. the first read of each class before that class is written. As built at most one of the four can hit per run, and the measurement shows all four at 0/N in every one of the 119 runs, while gen_fu_pmp1_covergroups.log states "NONE of the four groups has a bin that is unreachable". - Keep a written-flag per CSR class (or per CSR) and sample `yes` on a read-only access while that class is unwritten; until then the log and the plan must name the four cross bins as not reachable by the current sampler.

[Minor][dv/auto_dv/env/gen_fcov_pkg.sv:1867] The `ignored_mml_exec` predicate L && (X || (!R && W)) includes RWX=111; the RTL's is_mml_m_exec_cfg covers only {001, 010, 011, 101} and a locked RWX=111 row IS written under MML. The plan's cp_outcome prose ("L=1 with X=1 or RW=01") carries the same mismatch. It only bites in the unchanged branch (locked entry, RLB=0, MML=1, attempted c1111 reads ignored_mml_exec instead of ignored_lock). - Encode the four rows of is_mml_m_exec_cfg and align the plan wording.

[Minor][dv/auto_dv/env/gen_fcov_pkg.sv:1900-1904] CG-PMP-002 cp_outcome reads `written` whenever the readback equals the attempted value, so a locked entry (RLB=0) rewritten with its current value is booked written although the DUT ignored it; the plan's ignore_bins locked_rlb0_written says the lock always wins. - Decide ignored_self_lock / ignored_tor_lock from the pre-state rule and use the readback only to confirm.
