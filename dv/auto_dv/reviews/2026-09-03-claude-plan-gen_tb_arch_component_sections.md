**Findings**

[Medium][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:451] The `mie` fast-bit row is now verifiable and the proposed shim fallback does not work. `mie_csr_t::write_mask()` (tools/riscv-isa-sim/riscv/csrs.cc:993-1000) returns only MSIP/MTIP/MEIP plus S/H/LCOF/COP bits, so bits 16..30 never stick; and `csr_t::write` cannot bypass it because `mip_or_mie_csr_t::unlogged_write` is `final` and applies the same mask (csrs.h:373-383). Without a fix the model never takes a fast interrupt, which removes 15 of 18 lines from lock-step checking. - Replace the UNVERIFIED marker with the cite, drop the `csr_t::write` fallback, and specify the no-patch route that the header allows: subclass `mie_csr_t` overriding the private virtual `write_mask()` (private virtuals are overridable) and install it in `state.mie` and `state.csrmap[CSR_MIE]` at `gen_isa_reset`. Note for the same row that `select_an_interrupt_with_default_priority` (processor.cc:258-262 with `ctz`) already gives nonstandard bits priority over MEI/MSI/MTI and picks the lowest set bit, matching Ibex's NMI > fast(lowest id) > ext > sw > timer, so no priority emulation is needed. This retires the Q-DL-10 dependency for this item.

[Medium][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:424] "Per record the shim steps the model once" is not true for interrupt and trigger records. In `processor_t::step` the interrupt is taken inside the try block and the catch sets `n = instret` (execute.cc:244, 317-318), so a `step(1)` that takes an interrupt retires zero instructions; the same holds for trigger actions (execute.cc:340-345). The record carrying `rvfi_intr=1` therefore needs one step to take the interrupt and a second to execute the handler's first instruction; a single step compares handler-entry state against a record that already executed an instruction. - State the step rule per record class in C5.2: synchronous trap record = one step that retires nothing; `rvfi_intr` record (or a preceding `rvfi_ext_irq_valid`) = arm, step to take, verify pc/mcause/mepc, then step once more for the instruction; trigger-entry likewise. Make `gen_isa_step` return the retired count so the scoreboard can assert it.

[Medium][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:190] The image contract is stale. C3.3 says the sidecar checksum is "32-bit sum of words and word count" and defines `+gen_mem_image_sum=<hex>`, but `dv/auto_dv/stim/gen_elf2mem.py:112-117` emits `{"crc32", "count"}` as CRC-32 over little-endian `(index, word)` pairs and its docstring places a requirement on the SV consumer to recompute exactly that. An SV model built from this doc would never match. - Rewrite the sentence and the knob (`+gen_mem_image_crc32`) to the CRC-32 definition, and name the SV CRC routine that will consume `$readmemh` output in index order.

[Medium][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:198] "A sampled VPI read-back of N words from cocotb" is not feasible as written: `gen_mem_model` is an SV class (line 185) and class-object associative arrays are not VPI-visible, so cocotb cannot read them through a handle. Section 6 of DV_prompt requires backdoor memory loads to be verified by read-back, so the mechanism must be real. - Either add a bridge command (MEM_PEEK: addr in `cmd_arg`, data returned in a bridge field, awaited by edge) or make the read-back an SV-side check (model read of N seeded addresses against the words re-parsed from the image file) and record which one `gen_handles.py`'s "memory-sample handles" refers to.

[Medium][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:327] `irq_pending` is specified as an every-cycle compare with `mie_q` "from the CSR model (updates the cycle after the write retires)". `irq_pending_o` is combinational from `mie_q` (rtl/ibex_cs_registers.sv:1044-1045; AN s9 confirms zero latency), and `mie_q` is written when the CSR instruction executes in ID/EX, at least two cycles before its RVFI record (`rvfi_valid` follows WB by one cycle, more when WB stalls). Every retired `mie` write therefore produces a multi-cycle mismatch window and a false `uvm_error`. - Define the checker with a settle window opened at each retired write to `mie` (and around `mstatus`-independent pin edges it need not, since pins are visible), sized as a `gen_tb_pkg` constant derived from the pipeline depth and measured in bring-up like `GEN_IRQ_ENTRY_BOUND_RECORDS`; the same consideration applies to `crash_dump` fields updated at trap entry before the trap record appears (line 303 already limits itself to "from the cycle after", keep that pattern).

[Low][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:301] `alert_bus` says the alert asserts "in the cycle the core consumes" a corrupted response "and never otherwise". For fetch, `instr_intg_err_o = instr_intg_err & instr_rvalid_i` (rtl/ibex_if_stage.sv:282): the alert fires in the `rvalid` cycle of the corrupted beat whether or not the word is ever consumed (speculative or PMP-denied fetches included). As written the rule false-fails on any unconsumed corrupted fetch beat. - Split the expectation by source: fetch = the `instr_rvalid_i` cycle of the injected beat; load/store = the data response cycle (verify the LSU registration at bring-up).

[Low][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:506] The lock-step ISA string is never written down (C5.1 line 402 says only `isa`), and the standalone string on this line omits `zca_zcb_zcmp` although the build is `RV32ZcaZcbZcmp`; the standalone tool would reject every Zcmp program. - Define one ISA string in the generated constants (C11 codegen output to `gen_isa_shim_map.h`) and use it in both C5.1 and C5.6.

[Low][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:151] `ibus_order` lists mutation classes "n/a (TB self-check)". [Low][dv/auto_dv/work/tb-infra/gen_tb_arch_component_sections.md:362] `ctr_minstret` is "exact with dummies off; >= with dummies on unless P1", which makes a checker's strength depend on probe P1, while C8 line 578 states "No checker depends on any probe". - Pick one: keep P1 coverage-only and state that `ctr_minstret` is a bound check whenever `cpuctrlsts.dummy_instr_en` is set, or register the P1 dependency as a checker probe for the Critic.
