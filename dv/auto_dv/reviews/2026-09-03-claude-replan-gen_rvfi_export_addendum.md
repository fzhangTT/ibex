## Part 2: new defects in the diff since 4c0ba11

N1. The rewritten completeness rule (lines 74-81) reads "the LAST COMPLETE flush marker" with no binding to the flush the test just issued. `read(path)` (line 118) and `GenBridge.rvfi_flush()` (line 119) exchange nothing. In a test that flushes more than once, a missing later marker leaves an earlier complete marker whose prefix is self-consistent by construction, so `read()` returns stale phase-1 records and the fire-check runs on them; the `>=` check on `evt_retired_count` (line 79) cannot detect it. The removed "last line must be a marker" rule would have caught the records written after the stale marker, so the remediation weakened detection for this case. MUT-D's second clause (lines 139-140, "the marker's `records` differs from the parsed count") cannot fire for a stale marker, so the MUT-D proof only holds on a single-flush fixture.

N2. Line 128: "the tohost store as the last `R` line with `mem_wmask` F at the tohost address" is false for the named fixture. gen_zc_directed.S:150-154 follows the store with `1: j 1b`; nothing in the TB stops fetch on EOT (gen_bridge_if.sv:38-39 only toggles `evt_eot_seen`), and Python issues the flush from `fire_check()` after `wait_eot()` and the stimulus join (gen_test_template.py:326-334), so the last R lines are spin-loop jumps. The fixture as written goes red on a correct implementation.

N3. MUT-A (lines 134-135) is caught by "the fixture's pc continuity check between consecutive `R` lines", but the fixture's assert list at lines 124-129 contains no such check. Either the mutation is uncaught or the fixture is under-specified; the check also needs its rule across Zcmp folded records and traps (`pc_wdata(k) == pc_rdata(k+1)` holds for both, but the text should say so).

N4. Radix ambiguity: line 48 says values are written with `%h`/`%0d`, line 30 says R-line values are "hex without prefix", lines 31-33 leave the I-line `<cycle>` and the marker `records=`/`retired=`/`markers=`/`cycle=` radix unstated, and lines 78-79 require "hex-only tokens". A decimal token is valid hex, so a reader that parses a `%0d` column as hex is silently wrong (cycle 100 reads as 256) and no rule in Section 3 catches it.

N5. Line 120: "a new Section 8 'RVFI record export'" collides with the existing Section 8 "At build" in gen_component_api_rvfi_monitor.md:74.

N6. Lines 40-42 attribute `rs3_addr`/`rs3_rdata` to the CHERIoT carve-out, call them constant in this configuration, and say `rvfi_cap_quiet` owns them. rs3 is upstream Ibex: rtl/ibex_core.sv:2316-2317 loads `rvfi_rs3_addr_d = rf_raddr_a` on every non-first ID cycle of a multi-cycle instruction, so it is not constant; the `rvfi_cap_quiet` row (gen_tb_architecture.md:618) covers only `*_rcap` and `mem_is_cap`. Section 7(2) at line 171 repeats "the four CHERIoT-carve-out fields". Excluding rs3 is a legitimate choice; its stated basis is wrong.

Also checked and found consistent: `ext_exp_insn` carries the 16-bit cm.* encoding (gen_tb_architecture.md:829-830), so the cm.push/cm.pop count at lines 127-128 is a valid content assertion; the ap_irq rising-edge change (lines 53-56) has no subscriber in dv/auto_dv/env or tb, so it breaks nothing; `irq_markers=0` appears in all 43 retained evidence lines; the debug-only refusal (line 91) matches gen_run.py:207-212 and the loader check at gen_flow_util.py:303-305; the mutation id range MUT-009.. follows MUT-004..007 in dv/auto_dv/mutations/README.md:40 and MUT-008 in 9f521c6.

## Findings

[medium][dv/auto_dv/docs/gen_rvfi_export_addendum.md:74-81] `read()` is not bound to the flush just issued, so a test that flushes more than once passes on a stale earlier marker if a later marker is missing; the removed last-line rule caught this case and the new rule does not, and MUT-D's "records differs from the parsed count" clause (lines 139-140) cannot fire on a stale marker. - Add a flush identity to the marker (`seq=<cmd_seq>` or a flush index), have `GenBridge.rvfi_flush()` return it, make `read(path, seq)` require the last complete marker's seq to equal it, and state MUT-D on a two-flush fixture where the second marker is suppressed.

[low][dv/auto_dv/docs/gen_rvfi_export_addendum.md:128] "the tohost store as the last `R` line" is false: the Zc program spins `j 1b` after the store (gen_zc_directed.S:150-154), fetch is not stopped at EOT, and the flush is issued from `fire_check()` after EOT. - Assert instead that the last `R` line with a nonzero `mem_wmask` is the tohost store (`mem_wmask` F, `mem_addr` = tohost) and that every later `R` line is the spin jump.

[low][dv/auto_dv/docs/gen_rvfi_export_addendum.md:134-135] MUT-A's catch mechanism (pc continuity between consecutive `R` lines) is absent from the fixture's assert list at lines 124-129. - Add the continuity assertion to 5.1 and state its rule across Zcmp folded records and traps.

[low][dv/auto_dv/docs/gen_rvfi_export_addendum.md:48] `%h`/`%0d` without a per-column radix, while the reader's only rule is "hex-only tokens"; a decimal column parsed as hex is silently wrong. - Write every `R`/`I` value with `%h` and every marker `key=` value in decimal, and say so in the Section 2 format block.

[low][dv/auto_dv/docs/gen_rvfi_export_addendum.md:120] "a new Section 8" collides with the existing Section 8 "At build" of gen_component_api_rvfi_monitor.md:74. - Name it Section 9 or state the renumbering.

[low][dv/auto_dv/docs/gen_rvfi_export_addendum.md:40-42] `rs3_addr`/`rs3_rdata` are called CHERIoT carve-out, constant, and owned by `rvfi_cap_quiet`; they are upstream Ibex fields that mirror `rf_raddr_a` on non-first ID cycles (rtl/ibex_core.sv:2316-2317) and the `rvfi_cap_quiet` row covers only `*_rcap` and `mem_is_cap`. - Give rs3 its own exclusion basis (no consumer; not a Zbt ternary in RV32BOTEarlGrey) or export the two fields; fix "the four CHERIoT-carve-out fields" at line 171.
