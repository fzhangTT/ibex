## WS2 — REQUEST-CHANGES

The basic plumbing model is sound: the existing path is Makefile args → `RegressionMetadata` → `compile_tb.py`/`run_rtl.py` enable maps → YAML options → `get_tool_cmds()`. Whole-file `` `ifdef COCOTB_SIM`` guards with unconditional `.f` entries are also feasible. The plan has execution blockers around environment construction, UVM phasing, and Milestone B.

- [BLOCKER][WS2 §Task 4/7] The proposed simulator environment contains literal `PYTHONPATH=<repo>:$PYTHONPATH` and hard-codes `MODULE`. Commands are split with `shlex.split()` and passed directly to `subprocess.run()`, so `$PYTHONPATH` is never shell-expanded; the hard-coded module also defeats the overrides required by the watchdog test and Milestone B. See [riscvdv_interface.py](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/scripts/riscvdv_interface.py:132) and [scripts_lib.py](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/scripts/scripts_lib.py:77). — Substitute concrete values before argv construction and add an explicit/defaultable module knob, preserving caller `MODULE` overrides. Test both default and alternate modules.

- [HIGH][WS2 §Task 3/4/7] The plan explicitly defers two-level selection and never completes the binding `MODULE` + plusarg contract; the negative control uses an environment knob instead. See [WS2 plan](/localdev/fzhang/ws/ibex/docs/superpowers/plans/2026-09-01-ws2-cocotb.md:68) versus [spec](/localdev/fzhang/ws/ibex/docs/superpowers/specs/2026-09-01-auto-dv-setup-design.md:45). — Implement selectable `MODULE` and documented plusargs for stimulus parameters during WS2, and verify them in both milestones and `TB_CONTRACT.md`.

- [HIGH][WS2 §Task 2] `finish_on_completion=0` is conditioned on `cocotb_active` during a time-zero race, while the holder waits `#1` before checking active. The hello test can assert and clear active before that check, and cocotb may not have started when `run_test()` evaluates the condition. — Under `COCOTB_SIM`, set `finish_on_completion=0` unconditionally before `run_test()`. Have the holder wait for an explicit alive/activation handshake before waiting for deactivation; verify delayed startup and immediate-finish cases.

- [BLOCKER][WS2 §Task 7] `riscv_arithmetic_basic_test` does not generate interrupt-enabled software, whereas the existing interrupt tests use `+enable_interrupt=1`; Python-driven IRQs therefore are not guaranteed to enter a handler. There is also no listener/UVM-ready handshake, so early events may be lost or arrive before the sequencer exists. See [testlist.yaml](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/riscv_dv_extension/testlist.yaml:5) and the interrupt-enabled entry at [testlist.yaml](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/riscv_dv_extension/testlist.yaml:444). — Add a cocotb-specific interrupt-capable test entry with stock SV IRQ stimulus disabled, plus a UVM-listener-ready signal that Python awaits.

- [HIGH][WS2 §Task 7] Three `irq_raise_seq` triggers do not imply three handler entries: the sequence asserts multiple level-sensitive IRQs and does not drop them. The existing IRQ monitor observes line changes, not handler entry, and no Python-visible trustworthy counter is defined. — Use controlled raise/drop or request/ack cycles and export a dedicated handler-entry counter/event through the contract. Ablate that named checker for the negative control.

- [HIGH][WS2 §Task 4] The plan omits `scripts/ibex_sim.mk`. Its compile dependency set is currently only `SIMULATOR COV WAVES`, so a changed `COCOTB` value is not tracked; fresh-OUT-only tests conceal this. See [ibex_sim.mk](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/scripts/ibex_sim.mk:7). — Add `COCOTB` to compile-variable dependencies and explicitly modify both `compile_tb.py` and `run_rtl.py`; verify an on/off transition or document the mandatory fresh-OUT rule.

- [MEDIUM][WS2 §Task 2] The interface omits the spec’s compile-time macro flag bits, and the watchdog uses `$fatal` although the binding spec says `$finish`. See [spec](/localdev/fzhang/ws/ibex/docs/superpowers/specs/2026-09-01-auto-dv-setup-design.md:37). — Add the flag bits and follow `$finish`, or obtain an explicit spec amendment before using `$fatal`.

- [MEDIUM][WS2 §Task 2/7] The compilation/package order is left as “small pkg or include,” and Task 7 names nonexistent `core_ibex_vseqs.sv`; the actual file is [core_ibex_vseq.sv](/localdev/fzhang/ws/ibex/dv/uvm/core_ibex/tests/core_ibex_vseq.sv:1). — Specify exact `.f` ordering, package/import/include guards, and the actual listener location.

- [MEDIUM][WS2 §Task 2/4/5] Several compile-only commands lack the required `cd dv/uvm/core_ibex`, so they invoke the unrelated root Makefile. The watchdog “rerun sim stage only” can also be a no-op against an existing `rtl_sim.log`. — Make every command self-contained with the documented subshell and use a fresh OUT or explicitly invalidate the simulation target for negative tests.
