post-hardening re-run (WS5 final review fix wave)
---------------------------------------------------
Root cause for the "vcs missing" eager-MCP-spawn failure above (left "unexplained by anything
in this repo's control" in the sections above): each `ci/mcp/*.sh` wrapper does
`source ci/env.sh >/dev/null || exit 1`, and in codex's stripped MCP-spawn environment (no site
PATH, module loads no-op) `ci/env.sh`'s fail-loud tail (`command -v vcs || ... return 1`) returns
1 — killing the wrapper on a prerequisite (vcs) its server never needs. All exports the wrappers
DO need (`VERDI_HOME`, `IBEX_MCP_*`, the `$VERDI_HOME/bin` PATH prepend) are set before that
check runs, so the wrapper dies after getting what it needed but before `exec`ing the server.

Fix: `ci/env.sh` now honors `IBEX_ENV_TOOLCHECK=off` to skip the fail-loud tool-check block
(one stderr note when skipped; default behavior unchanged — see `docs/dv/process-logs/ws5/
progress.md` and the env.sh diff for the exact verification commands). Each `ci/mcp/*.sh`
wrapper exports that flag before sourcing `ci/env.sh`, then verifies its own real prerequisites
itself (`IBEX_MCP_*:?` guard, plus `VERDI_HOME` non-empty in `fsdb-mcp.sh`/`verdi-cov-mcp.sh`).

Confirmed the failure reproduces pre-fix and disappears post-fix, both under a stripped env
simulating codex's MCP-spawn environment (`env -i PATH=/usr/bin:/bin HOME=... python3
ci/mcp/probes/mcp_probe.py`): pre-fix, all three wrappers fail at `initialize` with
`ibex env ERROR: vcs missing` on stderr; post-fix, all three answer `tools/list` correctly
(same tool counts/names as above) in 1-3s each, with no site PATH or module loads present.
