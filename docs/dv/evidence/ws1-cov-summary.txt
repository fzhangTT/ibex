CRITICAL CAVEAT — the underlying test FAILED under COV=1, so the score
above is NOT representative of real coverage:
--------------------------------------------------------------------
regr.log: "0.00% PASS 0 PASSED, 1 FAILED"
trr.yaml: failure_mode FILE_ERROR(2), "Logfile trace_core_00000000.log not
found" (the RTL sim aborted before any trace was written).

Root cause (confirmed in rtl_sim_stdstreams.log): VCS raised a fatal
coverage "VERIFICATION ERROR" and terminated the simulation after only
2064350 ps (0.51s CPU time):

  Error-[FCIBH] Illegal bin hit
  dv/uvm/core_ibex/fcov/core_ibex_fcov_if.sv, 588 (covergroup core_ibex_fcov_if::uarch_cg)
  Illegal transition bin illegal_transitions of coverpoint cp_controller_fsm
  got hit with transition RESET=>RESET

This is a pre-existing, known VCS incompatibility, not something
introduced by WS1 bring-up work. The offending covergroup already
carries an in-source TODO (git blame: commit aee235cfa, 2022-03-24,
"[dv] Add cover points for memory interface behaviour" era):

  dv/uvm/core_ibex/fcov/core_ibex_fcov_if.sv:606-607 and :612-613
    // TODO: VCS does not implement default sequence so illegal_bins will be empty
    illegal_bins illegal_transitions = default sequence;

Because VCS does not implement SystemVerilog's `default sequence` for
transition bins, EVERY FSM state transition (including legal self-loops
such as RESET=>RESET during reset) falls into the "illegal" bin, and VCS
treats that as a fatal error rather than a benign coverage miss. This
only surfaces when the fcov covergroups are actually built/sampled,
which only happens under COV=1 (confirmed: Task 6's COV=0 run passed
+enable_ibex_fcov and -cm are both absent from that run's rtl_cmds in
out/run/tests/riscv_arithmetic_basic_test.1/trr.yaml). A quick check of
`vcs -help` found no documented runtime switch to demote FCIBH severity
from fatal to warning, so this is not a simple flow-level flag fix.

Practical effect: any COV=1 run today aborts within microseconds of
boot, before executing the test program. The merged.vdb/report/fcov
artifacts above are structurally well-formed (the merge_cov.py / urg /
get_fcov.py machinery all function correctly) but reflect essentially a
reset-only partial run, not real riscv_arithmetic_basic_test coverage.
This is a design/testbench-side fix (relaxing or restructuring the
cp_controller_fsm / cp_controller_fsm_sleep illegal_bins under VCS),
out of scope for this flow-bring-up task; flagged here for the WS1 gate
owner to decide on follow-up.
