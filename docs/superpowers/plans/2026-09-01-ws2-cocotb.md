# WS2: cocotb Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** cocotb 1.9.2 runs as an opt-in overlay on the existing VCS UVM TB — hello-world (Milestone A), then Python-driven irq stimulus through the UVM irq agent (Milestone B) — with the stock flow bit-identical when off.

**Architecture:** quasar_soc's coexistence pattern (cocotb is master; a `uvm_component` holds a run-phase objection while cocotb is active; `finish_on_completion=0`; cocotb polls `uvm_finished` before exiting) + ws-tensix's debug-access discipline (`+vpi -P cocotb_pli.tab` with `acc+=rw,wn:*` only; no new `-debug_access` flags) + a dead-cocotb watchdog. Flow plumbing mirrors how `WAVES`/`COV` knobs already travel Makefile → metadata → yaml substitution.

**Tech Stack:** cocotb 1.9.2 (venv), VCS X-2025.06-SP2, existing `dv/uvm/core_ibex` flow, DPI-exported UVM task for Milestone B.

**Spec:** `docs/superpowers/specs/2026-09-01-auto-dv-setup-design.md` (Workstream 2)

## Global Constraints

- `COCOTB=1` is strictly opt-in: with `COCOTB=0` (default) the VCS compile/run command lines contain **no** cocotb artifacts and the smoke test still passes.
- cocotb pinned `==1.9.2`; installed via the venv flow (lock regenerated PYTHONPATH-clean per `ci/setup-venv.sh`'s established pattern).
- VCS access for cocotb comes ONLY from `+vpi -P dv/uvm/core_ibex/cocotb_pli.tab -load $(cocotb-config --lib-name-path vpi vcs)`; the tab contains exactly `acc+=rw,wn:*`. Never add `-debug_access` flags (stock compile already carries `+pp`/`+f`).
- All SV additions live under `` `ifdef COCOTB_SIM `` (files may be unconditionally listed in `ibex_dv.f`; their contents compile away when the define is absent).
- Dead-cocotb watchdog: if Python has not set the alive bit by 100ns, the sim `$fatal`s with a clear message (a Python import error must fail in nanoseconds, not hang a license).
- Seeds: SV gets `+ntb_random_seed=<seed>` (existing); cocotb gets `RANDOM_SEED=<seed>` env var — same seed value, recorded together.
- Site rules from WS1 (binding): `module` exits 1 on success; poll logs directly, never park on notifications; `( cd dv/uvm/core_ibex && ... )` subshells; `REPO=$(git rev-parse --show-toplevel)`; never commit `out*/`; commits end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- Reference patterns (read-only): quasar `tb/sv/quasar_cocotb_if.sv`, `tb/env/quasar_cocotb_monitor.sv`, `tb/quasar_cocotb.py`; ws-tensix `src/t6ifc/vcs-core/CMakeLists.txt` + `catch_dead_cctb.sv`; cite what you borrow in one-line comments only where non-obvious.
