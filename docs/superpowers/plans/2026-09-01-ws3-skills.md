# WS3: Skills + Cross-Model Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The curated skill set, DV principles doc with the trust triad, review rubrics, agents, and the Claude↔codex cross-model layer — installed, validated, and demonstrated from both models.

**Architecture:** ws-tensix topology verbatim: canonical `.claude/skills/` + `CLAUDE.md` single source of truth; `AGENTS.md` thin delegator carrying only the duplicated critical invariants; `.agents/skills/shared → ../../.claude/skills` symlink; adapted `.codex/compat/validator.py` enforcing the contract in CI-runnable form. Skills are curated per the approved spec table — coding standards, reviews, TDD, mutation, fcov-expectation are the load-bearing content.

**Tech Stack:** Markdown skills (Claude Code `.claude/skills/*/SKILL.md` format), codex CLI 0.149.1, python validator, ibex flow facts from WS1 (`docs/dv/BUILD_AND_SIM.md` is the source of truth for commands).

**Spec:** `docs/superpowers/specs/2026-09-01-auto-dv-setup-design.md` (Workstream 3; trust-triad + cross-model policy sections are binding)

## Global Constraints

- Source materials (read-only references): ws-tensix `src/verif/tensix/instrn_issue/docs/conventions/dv_principles.md` (the base for ours), ws-tensix `AGENTS.md` + `.codex/compat/validator.py` + `.agents/skills/adapters/README.md` (topology), beowulf `ci/reviews/*.md` (rubric bases), beowulf `.claude/skills/{sim-debug,simple-english,lint-check}/`, beowulf `.claude/agents/*.md` (agent shapes), beowulf `meta/mutations/mutations.yml` (mutation-check inspiration).
- Never copy repo-specific nouns/paths from the source repos: every ported file is retargeted to ibex reality (commands from `docs/dv/BUILD_AND_SIM.md`, log names/layout from WS1, cocotb API from `docs/dv/TB_CONTRACT.md` if WS2 has landed it — otherwise leave cocotb hooks as one-line TODO-free "see TB_CONTRACT.md" pointers).
- `AGENTS.md` duplication budget: ONLY the critical invariants block (fence rules pointer + cross-review gate), verbatim-mirrored from CLAUDE.md and hash-checked by the validator; everything else is "read CLAUDE.md" delegation + client-mechanics translation.
- Cross-model review policy text (CLAUDE.md) must include: executing model never self-approves; pre-execution plan/spec review + post-execution diff review by the other model; artifacts under `docs/dv/reviews/` with reviewer identity (CLI version, model, reasoning setting) and explicit diff target; machine-readable verdict header (APPROVE / APPROVE-WITH-CHANGES / REQUEST-CHANGES); REQUEST-CHANGES gates progress until a recorded re-review; disagreements with recorded controller rulings go to the human, not the loop.
- Trust triad (dv_principles + skills must all agree, same wording): (1) TDD; (2) mutation-proof — a new checker/assertion counts only when a named mutation is caught by the named checker with hidden referees inert, plus a checker-ablation negative control; (3) fcov-expectation — new tests declare intended bins; declared-but-unhit bins fail the run, verified per-test pre-merge, generated covergroups namespaced, sampling anti-vacuity-reviewed.
- Site rules from WS1 (binding, encode into agents/skills where relevant): `module` exits 1 on success; background notifications unreliable — poll artifacts with deadlines; watchdog long-running subagents/shells; PYTHONPATH-clean pip operations.
- Never commit `out*/`; commits end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 4: Workflow skills — `sim-debug`, `regress`, `lint-check`, `dv-principles-check`

**Files:** Create `.claude/skills/{sim-debug,regress,lint-check,dv-principles-check}/SKILL.md`

**Interfaces:**
- `sim-debug`: input = test name or out-dir; procedure = locate newest `out*/run/tests/<t>.<s>/`, classify failure by stage using WS1's verified log names (gen → `compile.riscvdv.log` (0 bytes = clean) → `compile_tb_stdstreams.log` → `rtl_sim_stdstreams.log`/`rtl_sim.log` → `trr.yaml`), extract the minimal excerpt, check for cosim mismatch signatures (from `docs/dv/COSIM.md` §2), FCIBH note, watchdog `$fatal` note (cocotb). Output contract: stage, excerpt, hypothesis, next probe.
- `regress`: wraps the BUILD_AND_SIM.md commands (single test / TEST=all / COV=1), reminds fresh-OUT/metadata rules, reads `regr.log`/`report.html`/`regr_junit.xml`, summarizes pass rates + failure buckets by first-error signature.
- `lint-check`: discover and run the repo's actual lint entry points (inspect `lint/` and root Makefile targets — verible/verilator-lint; document exactly what exists and works TODAY; if a target is broken on this site, the skill says so rather than pretending).
- `dv-principles-check`: conformance review of a named diff/file against `docs/dv/dv_principles.md` §1-§6 (explicitly NOT a general code review; cites section numbers; never duplicates the doc).

- [ ] Step 1: write the four skills (frontmatter name/description per Claude Code format; procedures reference real paths/commands only).
- [ ] Step 2 (live test): run `sim-debug` mentally-executable check — feed it the WS1 FCIBH failure artifacts (they're described in `docs/dv/process-logs/ws1/task-7-report.md`): walking its procedure must reach "fcov illegal-bin fatal at ~2us" from the log names alone; adjust the skill if the procedure dead-ends.
